# Routes, shift locations, and account removal

Apply `supabase/migrations/20261014_live_location_and_accounts.sql` in Supabase SQL Editor before deploying this folder to Vercel. Existing installations must already have the clock-in and feature permissions migrations. New installations can use `supabase/setup_all.sql`.

- Remove a stop with × in the route review or tap its selected house again. During navigation tap **Edit stops**, remove a stop, then **Resume**. The next unvisited stop is retained, removed destinations and old requests are discarded, and an empty route ends navigation.
- Appointment setters have Shifts enabled by the migration. Clock In requests a fresh location and shows the updated sharing notice. Location permission is required to start a shift. Updates save about every 5 seconds while the app runs, and stop on clock-out/sign-out.
- Admin: open **Shifts** to see clocked-in staff on the map; select a person for their trail. Locations refresh every 5 seconds and show capture time and accuracy. Mobile browsers can suspend updates when locked/backgrounded, so this is a last-reported location view, not guaranteed background tracking.
- Admin Accounts **Delete profile** permanently removes a non-admin profile, Auth login, account-owned cascading history and the temporary archive in one transaction. Company leads and documents stay under existing foreign-key rules. Admin profiles remain protected. A constraint that prevents deletion rolls the whole operation back and surfaces an error.

Validation uses local regression tests and database simulation. No live Supabase or Vercel credentials were supplied, so remote deployment and real-device GPS checks must follow configuration.

Browser regression execution was blocked: no Chromium binary was installed and the browser download returned a truncated archive. Targeted route-state, location lifecycle/API, account deletion, and full fresh/repeat SQL simulation checks passed. Real-device and deployed browser checks remain required.

Location polling now updates existing map layers and roster text in place. Background errors retain the previous view, and same-user session refreshes preserve the Shifts screen and camera.
